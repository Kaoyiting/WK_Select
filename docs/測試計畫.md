# 測試計畫

> 版本：0.3.1 範圍收斂稿｜2026-10-27｜此為未來實作的測試設計，不代表本次已測試新系統。
> 依據 [需求規格](需求規格.md)、[API規格](API規格.md) 與 [資料庫設計](資料庫設計.md)。D-xx 未決項不得自行當正式驗收規則。

## 1. 範圍、環境與資料

一期測前台會員Google登入、後台管理員帳密（業主＋一位小幫手）、商品/圖片/CMS、人工代購需求、會員訂單、現貨人工補貨/自動扣回、人工付款/整單出貨與權限。二期增加正式金流沙盒、回呼、備份、部署與告警；三期增加兩店以上隔離與SaaS管理。成本/利潤、訪客下單、客戶代購需求表單與SaaS計費不在一期測試範圍。

測試環境使用獨立PostgreSQL與R2、Google測試帳號、金流沙盒。不得對正式客戶發測試通知、使用真實信用卡做壓力測試或把正式個資直接複製進CI。API交易測試必須用真正PostgreSQL；第三階段才加RLS測試，亦使用PostgreSQL，不以SQLite取代。

一期固定資料集：單一店家、兩個獨立帳密管理員（admin）、至少兩位Google會員及停用會員；現貨qty=0/1/多件、預購stock_qty=null、無售價、特價、無品牌、多圖、長標題商品；未綁會員人工聯絡人；不建立舊匿名匯入資料。兩tenant及跨店資料延到第三階段。UUID固定可重建，所有姓名/電話為測試資料。

## 2. 工具與測試層級

| 層級 | 工具提案 | 重點 |
| --- | --- | --- |
| 單元 | pytest、前端Vitest | 純計價、狀態機、選項驗證、JSON設定排序、前端錯誤顯示；不用真金流 |
| API/DB | pytest + httpx + PostgreSQL容器 | 會員/管理員授權、FK、交易回滾、冪等、版本衝突；RLS只列第三階段 |
| 整合 | Google測試client、R2測試bucket、金流sandbox | 真實供應商合約、錯誤與逾時；不可只mock所有外部流程 |
| 購物E2E | Playwright | 桌面/手機、登入→選規格→結帳→後台→出貨；保留截圖與trace |
| 負載 | Locust | 自有API/DB；外部供應商mock或核准測試，不壓Google/金流正式服務 |
| 還原/部署 | 容器化演練腳本與驗收紀錄 | 空環境安裝、migrations、備份還原、映像回滾及資料核對 |

單元測試不追求無意義覆蓋率。所有付款、庫存與權限分支須有正反案例；每個主要bug以能重現錯誤的測試保護。測試碼與實作同PR，不用鏡像實作的測試冒充規則驗證。

## 4. API、交易與安全案例

| ID | 操作 | 期望結果 |
| --- | --- | --- |
| A01 | 未登入POST /orders；直接呼叫舊匿名路由；僅admin cookie下單 | 401或舊路由停用；不建立訂單；後台登入不等於前台會員 |
| A02 | customer A查customer B訂單/付款 | 404；任何ID欄位替換也無法讀取 |
| A03 | Google會員呼叫admin；兩位管理員各自操作收款/退款與內容 | 會員401/403；兩位管理員同功能均可操作並記錄各自id |
| A04 | 缺CSRF、外站Origin、偽造tenant_id/role/total | 403或422；不寫入；回呼例外有簽章驗證 |
| A05 | 商品實價改變後用舊expected_total下單 | 409 PRICE_CHANGED；無殘留訂單/品項 |
| A06 | 兩個獨立DB連線同買最後一件現貨 | 恰一單成功、一單409；stock_qty=0；重送不重扣；預購null可下單且不扣 |
| A07 | qty0/負數/過大、現貨庫存0、關閉規格 | 422/409；不是將庫存0當無上限 |
| A08 | 同冪等key並行重送；同key換內容 | 同請求只有一單/同結果；不同內容409 |
| A09 | 建單中途注入DB錯誤 | 整筆回滾；無孤兒品項、付款或半完成冪等紀錄 |
| A10 | 取消兩次、出貨兩次、取消與出貨並行 | 版本/狀態保護；現貨建單扣一次、取消未出貨回補一次、出貨不再扣；回滾不殘留數量變動 |
| A11（三期） | 租戶A查B資料、缺少上下文、連線池重用 | 三期完成RLS後才驗收跨店隔離；不是一期發布門檻 |
| A12 | 跨product圖片綁variant、會員查別人訂單 | FK/授權拒絕；跨tenant外鍵另列三期 |
| A13 | 上下架、CMS更新expected_version已舊 | 409 VERSION_CONFLICT；不覆蓋新資料 |
| A14 | 人工需求未綁會員、新增外部URL | 能登錄/追蹤；不抓外部URL、不直接產生匿名訂單 |
| A15 | 會員停用/登出/權限變更後重用舊cookie | session撤銷或即時角色檢查阻擋 |
| A16 | 兩個會員讀取對方訂單 | 一律404；不依相同姓名或email放行 |
| A17 | upload錯誤、R2逾時、資產被引用刪除 | 明確錯誤；無壞圖發布；引用刪除409 |
| A18 | 直接存blob URL/本機路徑作商品圖片 | 拒絕；只接受同店有效asset_id |

一期不實作RLS或兩店驗收，只測單店會員本人資料與後台角色邊界。三期才用實際runtime非owner/NOBYPASSRLS角色測RLS、複合租戶FK及連線池；不得將未測的租戶隔離宣稱已完成。

| 管理員案例 | 期望 |
| --- | --- |
| 正確/錯誤帳密、不存在帳號、連續嘗試 | 正確可登入；失敗一致訊息；限流有效；不洩漏明文或hash |
| Google會員cookie呼叫admin；admin cookie呼叫/orders | 各自拒絕；兩套session及CSRF不可互換 |
| 業主與小幫手各自操作 | 稽核可辨識兩個admin id；小幫手與業主均可操作相同功能；兩位操作人仍有獨立稽核 |
| 改密碼、停用後重用舊session | 舊admin session失效；最後有效管理員不能被停用 |
| 現貨漏填/負數；預購stock_qty=null | 現貨拒絕不合法數量；預購不要求填寫，0與null不同 |

## 5. Google、圖片與前後台端到端

1. 未登入可看商品/詳細、多圖與空分類；加入購物車後結帳須Google登入。測試成功、拒絕授權、失敗、逾期及重新登入。
2. 登入後回到原購物流程，重新驗價；選顏色/尺寸，選有效711門市，檢查收件資料，提交只有一張會員訂單。
3. 後台人工新增聯絡人與代購需求、修改採購狀態，關聯既有商品/會員訂單；確認沒有成本欄位。
4. 管理員建立無品牌商品；本地檔案上傳與剪貼簿貼圖皆即時預覽；存檔、重整、另一瀏覽器及前台都能讀圖。若上傳失敗，不能只剩破圖圖示。
5. 長商品名、長品牌、長URL、不同價格寬度與按鈕，在列表可換行或受控橫向捲動；文字不覆蓋操作區。管理表格需可在手機完成編輯/下架。
6. 公告、投影片新增/編輯/顯示切換/順序調整，前台自動播放正確；顯示icon亮、隱藏暗且有可讀名稱。刪除限時連線後所有相依選單一致。
7. 富文字僅由CKEditor負責，金鑰未設定時明確停用；有授權測試時驗證儲存格式、重開及商品顯示一致，移除舊自製工具列。
8. 人工確認轉帳後，由管理員確認整單到齊再出貨；不要求逐項到貨量；保存物流號與確認人稽核，取貨付款依核准條件操作。
9. 手機390px、平板768px、桌面1440px；Chrome/Safari各至少一組實機或對應引擎。鍵盤操作、焦點、表單label、錯誤提示、觸控按鈕也要驗證。

自動E2E可在隔離測試環境使用受控OIDC測試provider/fixture；正式環境必須拒絕測試登入開關。staging仍需真Google測試帳號人工驗證，不能只靠繞過登入的session注入。

視覺驗收先記錄現有前台基準；React遷移保留版面。已確認的Google登入必要入口與登入導向另作差異清單，其餘不重新設計。

## 7. 負載測試提案（D-08待確認）

先在固定規格staging以1,000商品、10,000合成歷史訂單測試；記錄CPU/RAM/磁碟、映像版本、DB設定與測試資料，不將結果當無條件SLA。

- 情境L1：20個並行訪客，商品列表/詳情/內容讀取10分鐘，逐步升載。
- 情境L2：5個並行會員連續建立不同訂單5分鐘；外部Google/金流mock，測本機API/DB能力；另測庫存1的20人競爭，恰一單成立；取消後數量只回補一次。
- 情境L3：同時5個管理員讀寫與5MB圖片上傳，觀察資源、操作延遲及R2錯誤處理。
- 初始驗收提案：自有API讀取p95<500ms、建單p95<1s（不含外部供應商），非預期5xx<1%；金額/權限/現貨超賣及扣回錯誤容忍為0。此門檻需真實主機量測後由業主確認。
- 報告分開呈現預期409庫存衝突與非預期錯誤，記錄p50/p95/p99、吞吐量、DB鎖等待、最大連線、CPU/記憶體；不要只報平均值。

測試不得打正式第三方服務或無限建立真實付款。發現飽和後先調查SQL索引、連線池及圖片傳輸，不先引進分散式架構。

## 8. 部署、遷移與備份測試

- 空環境依文件能建立DB角色、schema、固定商家/兩位帳密管理員、啟動三服務；關機重啟資料存在。
- migration在舊版本樣本可升級；失敗不半套schema；固定版本映像可回復，但資料相容性要另核對。
- D1唯讀匯入對照商品/圖片/分類/導覽筆數、價格、舊ID連結與缺圖；不匯入訂單或會員，不觸發付款/扣庫存。
- 在隔離環境還原DB與R2清單，驗證單店資料、會員本人權限、兩位管理員帳密、圖片、訂單快照與付款紀錄；演練不發送通知/金流請求。
- 備份失敗、磁碟接近滿、健康檢查失敗、回呼異常各觸發測試告警，指定收件者實際收到。
- 切換後有新訂單時演練回滾對帳，不容許只切回舊站遺失新交易。
