# 資料庫設計

> 版本：0.3.1 實作對照稿｜2026-10-27。新版位於 `new-site/`；原站D1與程式保留。
> 本文件以目前單店PostgreSQL模型為準；金流與SaaS擴充明確另列，不視為一期完成。

## 1. 共通規則

- 一期一店一個資料庫。共通 `tenant_id VARCHAR(36)` 固定為單店UUID，僅作未來遷移識別；沒有商家切換、租戶成員表或RLS，不能開放多店共用。
- 資源ID使用伺服器產生的UUID字串；外鍵保留真實關聯，不讓客戶指定管理員或會員身分。
- 金額BIGINT、新臺幣整數元；庫存與數量INTEGER，不用浮點計價。
- 時間TIMESTAMPTZ儲存UTC，前端顯示當地時間；商品排序日期依Asia/Taipei產生。
- 有並行編輯風險的商品、規格、內容、客戶、需求、訂單與付款有version；更新需比對版本。
- 只有現貨規格stock_qty必填，預購NULL；0代表現貨無庫存，不表示不限量。
- 不建立成本、利潤、匯率成本、庫存預留或逐項到貨資料表。

## 2. 身分與工作階段

| 表 | 主要欄位 | 關聯／約束 |
| --- | --- | --- |
| `admin_accounts` | id、username、password_hash、status | username唯一且正規化；業主及小幫手不同帳密、相同完整權限；無角色分級 |
| `members` | id、google_sub、email、display_name、status | google_sub唯一；Google ID token驗證通過才建立；不存Google密碼 |
| `sessions` | id、kind、principal_id、token_hash、csrf_hash、csrf_token、expires_at、revoked | kind=admin/member；不同cookie/token/CSRF，不可互換；token_hash唯一；principal_id索引；principal關聯由service依kind驗證 |
| `admin_login_attempts` | key、count、window_at | 帳號與來源雜湊計數；不存在帳號也採相同驗證回應及限流 |

前台Google OAuth短期state/nonce/PKCE由Authlib與獨立簽署的短期flow cookie管理，不另建未使用的oauth_flows表；Google長期access/refresh token不保存。管理員密碼使用Argon2id；帳號建立/重設採受控CLI。改密碼及停用會撤銷相關session。

## 3. 商品與內容

| 表 | 主要欄位 | 關聯／索引 |
| --- | --- | --- |
| `products` | id、legacy_id、title、brand、category、country、kind、status、badge、price_amount?、sale_amount?、gallery JSON、image_colors JSON、description_html、size_guide_html、date、version | legacy_id唯一，保留舊商品連結；status索引；原價>=0，特價必須低於原價 |
| `product_variants` | id、product_id、color、size、stock_qty?、enabled、version | FK products；UNIQUE(product_id,color,size)；stock_qty非空時>=0；product_id索引 |
| `catalog_entries` | id、kind、name | kind=brands/categories；UNIQUE(kind,name)；一期品牌/分類共用簡單表，不建立兩套重複CRUD |
| `navigation_items` | id、parent_id?、label、action、action_value、placement、sort_order、enabled、version | parent FK自身；service禁止循環與超過三層；刪除有子項的列先拒絕 |
| `site_content` | key、value JSON、version | main設定包含品牌、公告、投影片、頁尾、共用HTML、CKEditor key與運費；公開輸出移除編輯器key |
| `assets` | id、object_key、mime_type、byte_size、width、height、sha256 | object_key唯一；上傳通過檔頭/解碼/大小驗證才建立紀錄 |

品牌是選填；商品存品牌/分類名稱作一期簡化。改名service會同交易更新商品及對應導覽，使用中名稱不能直接刪除。未來如需多分類再獨立設計，本期不預建多對多。

gallery保留有序圖片URL；image_colors是可選的圖片URL→規格顏色對照，必須由管理員指定，不推測對應。刪圖片需同步刪對照。靜態舊圖可使用assets相對路徑，新上傳以資產UUID的/media路徑引用。圖片上傳支援選檔及剪貼簿，兩者走同一API。

富文字後端白名單清理，保留安全字型大小/段落等格式，移除事件、script及危險URL。沒有CKEditor授權key時顯示預覽、編輯功能尚未啟用。

## 4. 客戶、人工需求與訂單

| 表 | 主要欄位 | 關聯／約束 |
| --- | --- | --- |
| `customers` | id、member_id?、name、phone、email、notes、version | member_id可空且唯一、FK members；人工聯絡人不等於可下單會員；notes只供後台 |
| `purchase_requests` | id、customer_id?、contact、requested_name、product_url、color、size、quantity、source、notes、status、product_id?、order_id?、version | FK customer/product/order；網址只記錄不抓取；不自動建立匿名訂單 |
| `orders` | id、order_number、member_id、status、subtotal_amount、shipping_amount、total_amount、receiver JSON、store JSON、shipping_method、payment_method、note、version、created_at | order_number唯一；member_id必填FK members且有索引；沒有legacy_import或舊訂單認領欄位 |
| `order_items` | id、order_id、product_id、variant_id、title、color、size、kind、unit_amount、quantity | FK order/product/variant；order_id索引；名稱、規格、類型、售價保存下單時快照 |
| `shipments` | id、order_id、tracking_number、confirmed_by、shipped_at | order_id唯一FK orders；confirmed_by FK admin_accounts；一次整單出貨，不另填逐項到貨量 |

收件與門市快照包含姓名/電話/Email、門市ID/名稱/地址。改會員或商品不回頭改舊單。原站沒有舊訂單，因此不做訂單/會員遷移。

### 現貨交易

1. 合併相同variant數量，依固定ID順序鎖定規格，重新驗價、驗已上架狀態及現貨數量。
2. 建單、明細、現貨扣減、初始付款紀錄及冪等結果同一交易提交；任一步失敗全回滾。
3. 預購stock_qty=NULL，不扣減；現貨0拒絕下單。並行購買最後一件只能一單成功。
4. 取消pending/confirmed且未出貨訂單，鎖定原規格及訂單，依品項kind快照回補現貨並改cancelled，同交易提交；重送不重補。
5. 出貨不再扣庫存。已出貨退貨/退款先人工處理，不自動回補。
6. 人工補貨與自動扣回均遞增規格/商品version，避免舊表單覆蓋新數量；有未出貨訂單時禁止切換供貨方式或移除規格。

## 5. 付款、防重複與稽核

| 表 | 主要欄位 | 約束 |
| --- | --- | --- |
| `payments` | id、order_id、status、amount、refunded_amount、reference、paid_at?、version | order_id唯一FK；一期每單一筆人工收退款紀錄，不代表執行線上收退款 |
| `idempotency_records` | id、actor_id、operation、key、request_hash、response JSON | UNIQUE(actor_id,operation,key)；PostgreSQL交易advisory lock保護同key並行；同key不同內容409 |
| `audit_logs` | id、admin_id?、action、target_id、detail JSON、created_at | 只記必要遮罩資料；runtime禁止UPDATE/DELETE；管理員操作保留各自ID |

狀態：商品draft/published/offline/archived；需求pending/purchasing/arrived/unavailable/closed；訂單pending/confirmed/shipped/completed/cancelled；人工付款unpaid/paid/partially_refunded/refunded。預留及自動到期不在一期。實際入帳/退款才人工確認；金額不符拒絕且不修改款項。

## 6. 遷移與權限

- `new-site/backend/migrations/versions/0001_initial.sql`固定初始schema，後續Alembic版本新增稽核權限、固定商家識別、圖片顏色對照及BIGINT金額；不從目前模型動態重建舊migration。
- db bootstrap/migration與runtime帳號分開；API不持有bootstrap密碼。資料庫沒有對主機公開5432。
- 本機資料來自原站唯讀商品/品牌/分類/導覽副本及現有網站預設內容；受保護商品圖已另存新版素材，原圖保留。
- 原站現貨總數量為0；不將它當無限量，也不假造每個尺寸庫存。複合規格按已知來源審查後匯入，業主需核對。
- 不執行舊D1寫入、雙寫或正式切換。未來切換另作最後資料核對與備份。

## 2026-10-27 商品特價時段補充

Migration 0006 新增 products.sale_starts_at、sale_ends_at（TIMESTAMPTZ，可空）。後台用台灣時間輸入，API傳帶時區的時間。兩者皆空則原有特價持續有效；開始時間包含該瞬間，結束時間不包含該瞬間。到期不改歷史訂單，伺服器建單重算回原價。

## Migration 0008
