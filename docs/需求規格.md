## 4. 階段與範圍

### 第一階段：單店自用

| 編號 | 功能 | 驗收重點 |
| --- | --- | --- |
| F-01 | 商品與規格 | 名稱、品牌選填、分類、來源、原價／特價、顏色、尺寸、現貨規格庫存（人工補貨、建單自動扣回）、上架狀態 |
| F-02 | 圖片 | 多張照片、顏色對應、排序、檔案上傳與貼圖即時預覽；儲存後前後台均可讀取 |
| F-03 | 商品與導覽 | 全部商品可點擊、不帶分類下拉；商品類別保留下拉；分類／品牌／導覽刪除與改名連動 |
| F-04 | 網站內容 | 公告、投影片、文字、圖片、頁尾可修改；顯示切換與排序；不增加任意程式碼編輯器 |
| F-05 | Google 會員 | 前台 Google 登入、建立會員、停權、登出、工作階段；匿名建立訂單一律拒絕；後台獨立帳密登入 |
| F-06 | 客戶管理 | 會員聯絡資料、歷史訂單；人工需求的聯絡人可先記錄，但不能形成訪客訂單 |
| F-07 | 代購需求 | 後台登錄網址、名稱、顏色、尺寸、數量、來源、備註與進度；可連結既有會員、商品或訂單 |
| F-08 | 購物與訂單 | 登入後重新驗價、驗規格與現貨庫存；業主填現貨數量，建單原子扣減、取消回補，不另做預留；收件／門市資料；防止重複下單；會員只能看自己的訂單 |
| F-09 | 付款紀錄 | 取貨付款／人工銀行轉帳紀錄及人工確認；紀錄確認人與時間，不以匯款截圖自動判定入帳 |
| F-10 | 出貨管理 | 商品到齊後整單寄出，人工登錄物流／追蹤資訊；7-11 地圖選店與物流交寄分開看待 |
| F-11 | 維運基礎 | 可重建的開發／測試環境、資料遷移、權限、錯誤日誌與可還原備份 |

一期不含：多商家營運、租戶成員系統、資料庫 RLS、自動庫存預留、逐項到貨數量、成本／利潤報表、外幣售價、自動比價抓站、自動採購、供應商對帳、客戶前台提交代購表單、訪客下單、優惠券、紅利、推薦碼、分期自建、平台抽成或多店訂閱計費。

### 第二階段：正式營運

- 正式網域、HTTPS、Google 正式 OAuth 設定、必要個資／服務政策。
- 綠界或確認後的金流商：付款交易、ATM 取號、正式付款通知、查帳與退款紀錄。
- 審核過的支付方式才可在結帳與頁尾顯示；金流與物流開通各自確認。
- 正式備份／還原演練、監控告警、權限驗收、容量基準與故障處理。
- 既有 D1／R2 資料移轉、歷史訂單存取及切換／回復演練。

### 第三階段：未來 SaaS

- 店家開通、獨立品牌與網域、租戶資料與檔案隔離。
- 商家訂閱、停用、續約、資料匯出與結束服務，商業條件待 D-10。
- 【設計提案】各店家以自己的金流商帳戶收取商品貨款；SaaS 訂閱費是另一類交易。不得把店家貨款混入平台訂閱收入。
- 本階段不在一期實作自助開店、訂閱扣款、平台代收分帳或跨店購物車。

| 角色 | 可做 | 不可做 |

| 未登入瀏覽者 | 【沿用現況】瀏覽公開商品、公開服務說明；可在瀏覽器暫存購物車 | 下單、取得付款帳號、讀取客戶或訂單資料 |
| 已登入會員 customer | 管理自己的聯絡資料、建立及讀取自己的訂單與付款狀態 | 改價、改庫存、看他人訂單、直接更改付款成功狀態 |
| 管理員 admin（業主與小幫手，各自帳密） | 本店商品、內容、客戶、需求、訂單、出貨、收款與退款紀錄、設定與稽核；兩人完全同權限 | 未登入操作、變造不可變訂單快照、跨店存取 |
| 金流通知來源 | 經驗章後更新指定交易結果 | 使用一般登入權限、任意指定租戶或訂單金額 |

管理員與前台會員是不同帳號體系。業主與一位小幫手使用管理員帳密，不必綁 Google，也不會因此取得客戶會員身分。已確認小幫手與業主權限完全相同；不做可自訂權限引擎。客戶資料可人工先建，但會員訂單必須綁定可驗證的 Google 會員。

## 6. 核心流程

### 6.1 會員下單

1. 公開瀏覽商品，前端購物車保存商品／規格 ID 與數量。
2. 點結帳，未登入則導向 Google；取消或失敗保留購物車。
3. 後端驗證 Google 回應，建立本店工作階段；首次登入建立本店會員。
4. 回到原結帳流程。後端重新計算售價、運費、規格與可購買數量。
5. 顯示最新金額；若價格改變，要求客戶確認新金額，不靜默多收費。
6. 建立訂單與不可變明細快照；重試同一請求不得再建一張訂單。業主填現貨數量，訂單成立在同交易扣減，取消未出貨單同交易回補；預購不扣庫存，不另做預留。
7. 一期顯示人工付款資訊／取貨付款；二期可建立金流交易。
8. 客戶以登入身分查詢自己的訂單；訂單成立不等於已付款或已採購。

### 6.2 後台人工代購需求

1. 操作員將接洽內容登錄為需求，網址只作參考，不自動抓取第三方網站。
2. 可關聯既有會員；若尚未是會員，僅記錄聯絡人與需求。
3. 進度依序可為待處理、採購中、已到貨、無法取得、已結案。
4. 一期以建立商品、請會員正常下單或關聯既有訂單銜接；不自動代客建立匿名訂單。
5. 缺貨、無法取得或款式變動記錄原因；需退款時進入人工處理，不能把需求狀態直接等同退款。

### 6.3 收款與出貨

- 人工銀行轉帳：店主確認實際入帳，再記錄金額、時間與對帳參考。
- 二期虛擬帳號：取號成功只代表「待付款」；驗證付款通知後才記錄已付款。
- 付款通知遺失時，透過後端查帳補正並保留稽核；不得由前端回跳直接改成已付款。
- 現貨與預購混合：由業主人工確認整張訂單商品到齊，再建立單一出貨紀錄；不要求逐項填到貨數量。
- 【設計提案】預付訂單需有效付款才能出貨；取貨付款例外須對應核准方式。正式條件見 D-02。
